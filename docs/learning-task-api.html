一、接口概览

模块路径为 bpm，管理端接口前缀为 /admin-api/bpm/learning-task，小程序端接口前缀为 /app-api/bpm/learning-center。

管理端 11 个接口小程序端 11 个接口统一 CommonResult<T>分页最大 100 条时间 yyyy-MM-dd HH:mm:ss
前端重点：资料列表返回的 materialId 用于创建任务；任务详情中的 taskMaterialId 用于打开任务资料、上报进度。上报附件时直接使用任务资料详情 text 中的附件 URL，并带上详情返回的 progressRevision。

二、公共约定

2.1 请求约定

项目约定
认证沿用平台登录态。学习接口从登录态取得当前用户 ID，调用方不传 learnerUserId。营销通用埋点另按约定由前端传 memberId=店长userId。
项目隔离所有接口依赖当前项目/业务上下文 businessId，不允许跨项目访问。
GET/DELETE参数放 Query String；数组参数使用同名参数重复传递，例如 taskPeriod=开始时间&taskPeriod=结束时间。
POST/PUTContent-Type: application/json，参数放 JSON Body。
时间LocalDateTime 按 yyyy-MM-dd HH:mm:ss 传递，例如 2026-09-15 00:00:00。
Long 精度所有 ID 的后端类型为 Long。JavaScript 端建议按字符串保存和透传，避免超过 Number.MAX_SAFE_INTEGER 后精度丢失。
百分比progressRate、completionRate 返回 0～100 的数值，保留两位小数，不是 0～1 的小数。

2.2 公共响应

{
  "code": 0,
  "data": {},
  "msg": ""
}
字段类型说明
codeInteger0 表示成功，非 0 表示校验或业务异常。
dataObject / Array / Boolean / Long实际接口数据；类型以各接口说明为准。
msgString成功或异常提示文案，前端失败时可直接展示。

2.3 分页响应

{
  "code": 0,
  "data": {
    "list": [],
    "total": 0
  },
  "msg": ""
}
字段类型说明
pageNoInteger请求字段，页码从 1 开始，默认 1。
pageSizeInteger请求字段，每页 1～100 条，默认 10。
data.listArray当前页数据。
data.totalLong满足条件的数据总数。

三、枚举与核心标识

字段值含义
管理端 taskStatus0 / 1 / 2按任务周期：未开始 / 进行中 / 已结束
小程序 taskStatus0 / 1 / 2按开始时间和必学资料进度：未开始 / 进行中 / 已完成
studyStatus0 / 1 / 2学习状态；小程序任务顶部兼容字段与 taskStatus 相同，资料状态按自身进度计算
onlineStatus0 / 1下架 / 上架
applyScope1 / 2按门店 / 按标签
storeScope1 / 2全部门店 / 部分门店
orderLimitType0 / 1不限制订货 / 限制订货
字段值含义
attachmentType1 / 2视频 / 图片
documentBrowseLimitType0 / 1不限制时长 / 限制最少浏览时长
eventType1 / 2 / 3打开 / 心跳 / 结束或完成申报
actionType1 / 2开始学习 / 查看任务
fileType1 / 2 / 其他视频 / 图片 / 文档或正文
requiredFlagtrue / false必学 / 非必学
标识来源使用位置
taskId创建任务返回或任务列表返回任务详情、上下架、删除、访问统计、任务访问。
materialId外部学习资料主表选择资料、普通资料详情/访问、创建任务的 materialItems。
taskMaterialId任务与资料关系表任务资料详情、文件进度上报；不能使用 materialId 代替。
fileUrl任务资料详情 text 中的视频/图片节点 url，或文档节点 file.url进度上报时定位当前附件；富文本不传。
fileKey富文本固定值 rich-text；附件稳定键可从 files 取得混排资料上报富文本时传 rich-text；附件新客户端使用 fileUrl。
fileVersion任务资料详情的 files 辅助数据仅兼容旧版附件上报。
progressRevision任务资料详情返回资料附件发生变化后递增，用于拒绝旧页面继续上报。
eventType / eventId / memberId营销通用埋点字段学习任务固定 eventType=learning_task；eventId 传任务 ID；memberId 传登录店长 userId。每次进入页面上报一次。

四、推荐调用流程

4.1 管理端创建/编辑

  1. 调用“可选资料分页”获取 materialId。
  2. 前端完成门店/标签范围选择和资料规则配置。
  3. 创建时调用 /create；编辑时先调用 /get 回显，再把当前完整资料列表提交到 /update。
  4. 任务创建后默认为下架，确认配置无误后调用“上下架”接口。

4.2 小程序学习

  1. 调用“我的任务”获得 taskId。
  2. 打开任务详情后异步调用“任务访问”，不要让访问统计失败阻断页面展示。
  3. 从任务详情取得 taskMaterialId，再调用“任务资料详情”。
  4. 保存详情返回的 progressRevision；渲染 text 时保存当前附件的 url（文档为 file.url）。
  5. 打开文件报 eventType=1，学习期间周期性报 eventType=2，视频播放结束报 eventType=3；文档、图片或富文本浏览到底部可报 reachedBottom=true，也可报 eventType=3。
  6. 收到资料变更类错误时，停止旧页面心跳并重新请求任务资料详情。

POST/admin-api/bpm/learning-task/create创建学习任务

参数位置：JSON Body　响应：CommonResult<Long>，data 为新任务 ID；新任务默认下架。

顶层请求字段

字段类型必填校验及说明
taskIdLong否创建时不要传
taskNameString是非空，最多 50 个字符
coverImageUrlString是任务封面地址
detailAttachmentsAttachmentReqVO[]否任务详情图片/视频，最多 5 个；不会影响资料学习进度
startTimeLocalDateTime是支持 yyyy-MM-dd HH:mm:ss 字符串或 13 位毫秒时间戳
endTimeLocalDateTime是格式同 startTime，且必须晚于 startTime
taskDescriptionString否最多 500 个字符
applyScopeInteger是1按门店、2按标签
storeScopeInteger条件必填applyScope=1 时必传；1全部门店、2部分门店
storeIdsLong[]条件必填applyScope=1 且 storeScope=2 时至少一项
tagIdsLong[]条件必填applyScope=2 时至少一项；多个标签按并集匹配
orderLimitTypeInteger是0不限制、1限制
orderLimitDaysInteger条件必填orderLimitType=1 时必填，范围 3～365 天
materialItemsMaterialReqVO[]是至少一项且至少一项 requiredFlag=true；同一个 materialId 不得重复。编辑时也必须保留必学资料
removedTaskMaterialIdsLong[]否创建时不传或传空数组；当前后端仅保留该字段，实际移除以 materialItems 完整列表为准

detailAttachments 元素

字段类型必填说明
attachmentUrlString是附件访问地址
attachmentTypeInteger是1视频、2图片
任务详情附件不需要传 sort，后端按 detailAttachments 数组顺序保存。学习资料的拖拽排序仍使用 materialItems[].sort。

materialItems 元素

字段类型必填说明
taskMaterialIdLong否创建时不要传
materialIdLong是外部学习资料 ID
documentBrowseLimitTypeInteger是0不限制、1限制最少浏览时长
minDocumentBrowseSecondsInteger条件必填documentBrowseLimitType=1 时必须大于 0
videoSpeedAllowedBoolean是视频是否允许倍速
requiredFlagBoolean是是否必学；任务总进度只计算当前有效的必学资料
sortInteger是大于等于 0

PUT/admin-api/bpm/learning-task/update修改学习任务

参数位置：JSON Body　响应：CommonResult<Boolean>

请求结构与创建接口相同，但 taskId 必须传入。已有资料应保留详情接口返回的 taskMaterialId；新增资料的 taskMaterialId 传 null 或不传。

编辑场景传参规则进度影响
修改任务名称、描述、封面、任务详情附件提交最新值不重置资料学习进度
修改资料排序、必学、浏览时长、倍速规则保留 taskMaterialId，提交最新规则附件未变时保留原始学习证据，并按当前规则重新计算状态
新增资料新增 materialItems 元素，不传 taskMaterialId新增资料从未开始计算
移除资料从 materialItems 完整列表中删除；removedTaskMaterialIds 可同步传递，但当前实际移除以完整列表差集为准历史进度记录保留但不参与当前任务进度
资料主表附件发生变化无需任务端主动提交附件对应关系 progressRevision 递增，旧进度失效
完整列表语义：materialItems 必须提交编辑完成后的完整资料列表，不能只提交发生变化的一项，否则未提交的资料会被视为移除。

截止时间 = startTime + orderLimitDays。例如 9 月 16 日 10:00 开始、限制 3 天，则 9 月 19 日 10:00 到期，与首次打开任务或首次学习时间无关。remainingDays > 0 时可展示“请在 X 天内完成学习”；为 null 时不展示倒计时，不能当作 0。是否允许订货始终以 canOrder 为准，不能只看剩余天数。

多个任务分别计算截止时间，只从未完成任务中选最早到期的一项。若 3 天任务和 4 天任务同时开始：第 3 天 3 天任务未完成会阻止订货；完成该任务后，第 4 天任务尚未到期时仍可订货；第 4 天任务到期仍未完成则再次阻止订货。

只检查当前项目、当前店长名下任一正常门店匹配的范围内已上架、已开始、orderLimitType=1 的任务。店长负责多家门店时，只要其中一家命中任务就按店长个人进度校验；全部门店都未命中任务时直接允许订货，remainingDays 和 taskId 为空。未开始、下架、删除的任务不参与；已结束但仍上架的任务继续参与，补学完成后放行。按店长用户共享进度，门店更换店长后按新店长的进度判断。资料下架、删除或改为非必学后不再限制，附件变化及文档时长修改按当前内容和规则判断。

本接口对正常的“未学完不能订货”返回 code=0、canOrder=false，前端可用 taskId 跳转任务并自行展示提示。命中放行配置时直接返回 canOrder=true，remainingDays 和 taskId 为 null，不再查询学习任务。普通查询为只读、按批次加载，不调用 ES、不更新进度。订货页面应接入该校验；本次接口不修改现有下单接口的其他规则。

十、关键业务规则与联调注意事项

  1. 资料实时性：任务关系只保存 materialId 和任务规则。资料名称、正文、分类、附件、上下架状态均实时读取资料主表。
  2. 下架资料：小程序直接隐藏；管理端保留关系并标记不可用。重新上架后自动恢复显示。
  3. 进度重置：修改资料文案、分类、封面或任务详情附件不重置；资料附件指纹变化会递增 progressRevision，旧修订进度不再参与计算。
  4. A→B→A：以重新上架时最终附件与上次有效附件比较；最终完全相同则不重置，这是已确认的业务口径。
  5. 多门店同步：学习进度以负责人用户为主维度。同一人管理 3 家目标门店，在任一家学习后，另外 2 家展示相同进度。
  6. 任务状态：开始时间之前为未开始；开始后，当前有效且 requiredFlag=true 的资料全部完成为已完成，否则为进行中。创建和编辑任务时至少保留一项必学资料。非必学资料不影响任务总完成率。
  7. 任务时间：开始前可查看但不能上报进度；结束后仍允许补学。
  8. 访问统计：任务 PV/UV 写入 ES，不参与数据库事务。详情展示与访问上报必须解耦。
  9. 并发控制：同一 taskId + learnerUserId 的进度上报串行处理。前端不要同时启动多个心跳定时器。
  10. 订货限制：只调用 /task/order-limit/check，一次取得 remainingDays、canOrder，以及最近到期的未完成任务 taskId。未到“任务开始时间＋限制天数”允许订货，到期且未学完才拦截；无有效必学资料不限制。命中 Nacos 店长 userId 放行配置时直接返回 canOrder=true，remainingDays 和 taskId 均为 null。
当前实现边界：普通资料列表和详情的 viewerCount 当前填充为 0；任务访问统计已经接入 ES。若前端需要展示普通资料真实浏览人数，需要后续补充普通资料统计读取逻辑。
