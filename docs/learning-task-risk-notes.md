# 学习任务实现风险与约定

## 已确认的业务约定

1. 学习任务只保存 `material_id`，标题、文案、分类、上下架状态和附件列表均实时读取学习资料主表。
2. 资料下架后，任务端隐藏该资料但保留任务关系；重新上架后自动恢复展示。
3. 标题、摘要、富文本、分类和任务详情附件变化不重置学习进度；资料内部文档、图片、视频附件变化才重置该资料进度。
4. 附件替换必须生成新地址，不允许用原地址覆盖文件内容。
5. 用户同时负责多家命中门店时，用户主进度只保存一份，并同步投影到全部门店；PV、UV仍按用户去重。
6. 门店更换负责人后，新负责人从未开始状态学习；原负责人的历史进度保留。
7. 没有有效必学资料时，任务进度为0、状态为未开始，订货限制暂停。

## 必须保留的指纹边界

> 资料附件从 A 改成 B，之后又恢复成完全相同的 A，如果期间没有任务接口访问，任务侧无法识别中间变化。由于资料只能下架后编辑，本方案以重新上架时的最终附件内容和上次有效内容比较；最终内容完全相同则不重置进度。

该行为属于已接受的产品定义，而不是程序缺陷。如果未来要求识别每一次中间变更，必须由学习资料模块提供单调递增的附件版本号或变更事件；仅靠任务侧最终内容指纹无法恢复未观察到的历史状态。

## 仍需关注的工程风险

- 指纹规范漂移：文件字段的规范化顺序、空值规则和SHA-256算法不得随意调整，否则会导致全量误重置。变更解析规则前必须准备兼容版本。
- 非法JSON：学习资料 `text` 不是合法数组，或附件节点缺少URL时，接口返回“学习资料内容异常，暂时无法学习”，同时记录 `businessId/materialId` 错误日志。
- 并发上报：文件进度使用唯一键和乐观版本，冲突最多重试2次；仍失败时提示“学习进度已变化，请刷新后重试”。禁止无限重试。
- 心跳作弊与后台停留：服务端只累计相邻心跳的时间差，单次最多30秒，超过45秒的断档不计时；前端失焦、切后台、关闭页面后必须停止心跳。
- ES可用性：任务详情与访问上报分离。ES写失败不阻止打开任务，前端以同一个 `visitId` 静默重试；统计查询失败时明确报错，不伪造0。
- UV误差：ES cardinality 使用 `precision_threshold=40000`，超过阈值后UV为近似值，报表说明应标注。
- 门店动态范围：按标签任务、全部门店任务和负责人变更会使目标门店实时变化。主进度不复制；门店统计直接关联当前负责人主进度，轻量投影只在真实进度上报后同步，不能作为统计事实来源。
- 逻辑删除唯一键：任务移除资料关系时关系行物理删除，但文件/资料进度历史不删除；否则 `(task_id, material_id)` 唯一键会阻止重新添加。
- 连接池保护：批量ID查询每批最多500；禁止 `CompletableFuture` 并发查询数据库；列表正常读取必须批量预取，只有乐观锁冲突或检测到附件变化时才允许按行回读/更新；导出必须分页拉取。
- 状态筛选边界：附件修订采用任务接口访问时的惰性检测。若用户第一次访问就按“学习状态”筛选，而数据库仍是旧聚合状态，该任务可能要先在“不限状态”列表或详情中完成一次修订同步后才进入正确筛选结果。若产品要求任何筛选入口都绝对实时，需要资料模块发布附件变更事件，任务侧消费事件后主动修订，不能靠查询时指纹完全解决。
- 死锁保护：事务内按主键升序处理关系；JSON解析和ES调用放在事务外；事务只做必要的数据库写入。

## 上线前检查

1. 在预发执行 `sql/bpm_learning_task.sql`，核对表、唯一键、组合索引与字符集。
2. 对管理端分页、App任务分页、当前修订进度查询分别执行 `EXPLAIN ANALYZE`，确认没有全表扫描和超大临时表。
3. 压测同一用户并发心跳、同一负责人多门店、资料下架/编辑/重新上架、门店负责人更换。
4. 验证ES按月索引权限、模板/映射、409幂等、跨月统计和无索引场景。
5. 验证订货限制调用方只读取“当前有效必学资料”计算后的任务状态。
