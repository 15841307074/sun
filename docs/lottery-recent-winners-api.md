# 小程序最近中奖记录

## 请求

`GET /app-api/promotion/lottery-mobile/recent-winners?activityId=活动ID`

- 沿用小程序现有登录、项目上下文。
- `activityId` 必填，传活动主表 `activity.id`（详情返回的 `cacheData.activityId`）。直接按项目、活动读取 Redis，不查库验证或转换配置 ID；传入配置 ID 将无法读取对应活动的缓存。原 `lotteryId` 参数已移除，单独传原参数会因缺少 `activityId` 返回 HTTP 400。
- 汇总当前活动所有门店已写入缓存的中奖记录，按记录时间倒序返回最新 20 条，不足 20 条返回实际条数，无缓存返回 `[]`，不回查历史中奖表。
- 排除抽奖时标记为兜底的奖品，同时排除“无奖品”。同一用户多次真实中奖会显示多条。

```json
{
  "code": 0,
  "data": [
    {"memberMobile": "159****5152", "prizeName": "100积分"},
    {"memberMobile": "138****1234", "prizeName": "10元优惠券"}
  ],
  "msg": ""
}
```

## 缓存更新

- 键：`lottery:v2:{b项目ID:a活动主表ID}:winners:recent`。项目、活动隔离；同一活动所有门店共用一份缓存。
- 新旧抽奖流程均在中奖记录保存成功后更新。事务内调用时，在提交后发布；回滚不发布。
- 非兜底中奖记录保存成功后，通过 Redis Lua 原子合并、排序、去重、截断至 20 条，支持多实例同时写入。
- 缓存只存脱敏手机号和奖品展示信息，不保存完整手机号。
- 展示集合固定在中奖记录中的活动结束时间加 7 天过期，查询不续期。取消完整性标记、回填锁和数据库回填；Redis 丢失或写入失败的展示记录不补查，不影响中奖与发奖业务。
- 部署前已存在的展示集合在下一条非兜底中奖记录写入时更新为上述过期时刻，不扫描或回查数据库迁移缓存。
- V2 红包处理中不提前展示，发奖完成并写入中奖记录后展示。

## 数据库发布

在每个中奖记录实际物理库执行 `sql/lottery_release_all.sql`，将 `@lottery_release_target` 设为 `LOG`，再发布服务。脚本新增中奖时的 `is_guarantees` 快照和查询索引。

本次展示缓存调整不新增表或索引。历史中奖记录不通过查库或 SQL 回填滚动列表；无缓存时从后续新产生的非兜底中奖记录开始展示。
