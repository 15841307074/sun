# 小程序最近中奖记录

## 请求

`GET /app-api/promotion/lottery-mobile/recent-winners?lotteryId=活动ID`

- 沿用小程序现有登录、项目上下文。
- `lotteryId` 必填，支持活动主表 ID 或抽奖配置 ID；建议前端统一传活动主表 ID。
- 汇总当前活动所有门店，按记录时间倒序返回最新 20 条，不足 20 条返回实际条数，无记录返回 `[]`。
- 排除抽奖时标记为兜底的奖品，同时排除“无奖品”。同一用户多次真实中奖会显示多条。

```json
{
  "code": 0,
  "data": [
    {"memberMobile": "159****5152", "prizeName": "100积分"},
    {"memberMobile": "138****1234", "prizeName": "10元优惠券"}
  ],
  "msg": ""
}
```

## 缓存更新

- 键：`lottery:v2:{b项目ID:a活动主表ID}:winners:recent`。项目、活动隔离；两个活动 ID 入口共用一份缓存。
- 新旧抽奖流程均在中奖记录保存成功后更新。事务内调用时，在提交后发布；回滚不发布。
- Redis Lua 原子合并、排序、去重、截断至 20 条。冷缓存回填采用合并，避免覆盖并发产生的新记录。
- 缓存只存脱敏手机号和奖品展示信息，不保存完整手机号。
- 展示集合保留 24 小时；完整性标记 60 秒到期后受控回源，补齐缓存更新失败期间的记录。一个活动仅允许一个并发回填，单实例回填并发上限 4。
- V2 红包处理中不提前展示，发奖完成并写入中奖记录后展示。

## 数据库发布

在每个中奖记录实际物理库执行 `sql/lottery_release_all.sql`，将 `@lottery_release_target` 设为 `LOG`，再发布服务。脚本新增中奖时的 `is_guarantees` 快照和查询索引。

历史记录没有兜底快照，需核对当时的奖品配置后回填；未核对记录保留 `NULL`，不出现在滚动列表中。脚本附有回填示例，不能直接把所有历史空值设为 `0`。
