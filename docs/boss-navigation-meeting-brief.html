登录后的四层判断

项目决定范围，角色决定入口，功能决定是否选择门店。

01 · 项目
先确定当前项目

登录用户可用项目来自 getBusinessListByUser。单项目可直进；多项目先选项目。后续导航权限按当前 business-id 查。

02 · 功能
入口由菜单决定

getNavigationByRole 将当前项目角色的启用菜单映射为进货、OA、数据、管理、订单 5 个布尔值。一个入口可直进，多个显示工作台。

03 · 门店
选择发生在点功能时

门店相关功能先从 storeListByBoss 拿可访问门店；若该功能需要门店，1 家直进，多家弹门店选择。项目选择和门店选择是两件事。

04 · 例外
“有门店”不等于“有权限”

菜单入口与门店数据来自不同逻辑。必须同时校验功能权限、项目上下文和目标门店；空门店、角色失效、状态变化都要单独处理。

需求与实现边界：“1 个入口自动跳转、按功能决定是否选门店”来自需求图；当前两个接口提供权限和门店数据，客户端跳转行为需要另行落实。

从登录到功能页

按项目、权限和门店依次收窄可进入的范围。

STEP 01

账号登录

先验证 token，再读当前账号的可用项目。无可用项目要给出明确提示。

STEP 02

确定项目

1 个项目：直接设为当前项目。多个项目：展示“选择项目”，选后带上 business-id。

STEP 03

算入口

接口返回与判断依据

以下规则以当前后端代码为准。

接口 A · GET /app-api/system/user/boss/getNavigationByRole

Controller 路径为 /system/user/boss/getNavigationByRole；经 app 网关时为上方路径。无业务请求体；依赖登录用户和当前 business-id。

字段何时为 true说明 / 限制
isPurchase有效菜单含进货菜单 ID普通门店数为 0 时也可能为 true
isOA有效菜单含 OA 菜单 ID普通门店数为 0 时也可能为 true
isData有效菜单含数据中心菜单 ID，且普通门店数 > 0普通门店数为 0 时强制 false
isManagement有效菜单含管理菜单 ID，且普通门店数 > 0是合并的“管理”入口，未拆商品/门店/外卖/会员
isOrder有效菜单含订单菜单 ID普通门店数为 0 时也可能为 true；门店选择规则未定义
isManyStore另行统计的普通门店数 > 10 家和 1 家都为 false；不能用 false 推断“恰好 1 家”
isMyPermissions当前实现没有设置 true默认 false；不支持直接决定“我的”页是 2 栏还是 4 栏
计算口径：角色按当前项目获取，禁用角色被移除，菜单也过滤禁用项。isManyStore 的计数来自组织及子组织门店 + 当前项目下直接关联门店，要求门店未删除且 storeStatus=0；供应链门店查询结果在此方法中未参与计数。

接口 B · GET /app-api/system/store/storeListByBoss

Controller 路径为 /system/store/storeListByBoss。返回门店数组，流程判断常用字段为 storeId、storeName、orgId、visible、storeStatus、openStatus、useStatus、projectId、projectName；VO 还有地址、外卖与供应链等字段。

普通门店
组织及子组织范围，或用户直接关联且 visible=1 的门店；查询含 storeSource=0、未删除、storeStatus=0。直接关联分支与基础筛选的 SQL 优先级需联调核实。
供应链门店
按门店 userId=当前用户，且 businessId=11 / 当前项目 / null；要求未删除、storeStatus=0。当前查询没有额外按 useStatus=1 过滤。
去重与可见
以 storeId 去重，普通门店优先。visible 先取用户-门店直接关系；否则取最近关联祖先组织的可见值；没有则记 0。列表可能包含 visible=0 的项，前端不能把“返回了”理解成“可选择”。
顺序与状态
没有明确排序保证。需求图中的“营业中/歇业”“堂食/外卖”展示与禁选规则，需要根据字段和产品规则另定；storeStatus=0、openStatus、useStatus 不是同一概念。

支撑接口 · GET /app-api/system/business/dc/getBusinessListByUser

该接口负责“有哪些项目可以选”，会排除停用和过期项目，并返回每个项目的 roleNames。多项目时，个别项目即使没有角色也可能留在列表里；选中后才由导航接口报无角色。项目上下文由请求头 business-id 传入，切换项目时要刷新下游数据。

常见问题

点击问题查看页面行为和接口依据。

Q1：同一账号有三个项目，是登录后先展示工作台，还是先选项目？

按需求图先选项目。项目选择由 getBusinessListByUser 支撑；选中后带当前 business-id 再请求导航权限。不能拿 A 项目的菜单用于 B 项目。

Q2：单项目、单门店是否一定一路直达？

不是。“单入口”才决定是否跳过工作台；“单门店”只决定需门店功能是否跳过门店弹窗。若有多个功能入口，仍应先显示工作台。

Q3：为什么有权限看到 icon，点进去却提示无门店？

菜单权限和门店数据独立。尤其进货、OA、订单不被当前导航接口的 0 门店逻辑关闭。产品需确定空门店文案与是否禁用入口。

Q4：isManyStore=false 就代表只有一家店吗？

不代表。代码在 0 家和 1 家时都返回 false；供应链门店也不参与该计数。决定是否弹门店选择前，要查看实际候选列表。

Q5：门店列表有三家，为什么只显示两家可以选？

列表返回不等于可选。visible=0 可能仍出现在响应中；还需按当前项目、功能、使用/营业状态做过滤，具体过滤规则待确认。

Q6：一个项目没有角色，能不能出现在“选择项目”里？

当前项目列表接口在多项目时可能返回 roleNames=[] 的项目；选中后导航接口会抛“未绑定角色，请联系运营经理”。建议前端将其禁选并说明原因，或由后端在列表阶段过滤。

Q7：切换项目后，原来选的门店和当前页面还能保留吗？

不建议保留。项目切换要清空已选门店和功能上下文，重新拉项目角色菜单与候选门店，避免跨项目串数据。

Q8：商品管理、门店设置、外卖设置、会员管理能直接根据 isManagement 展示吗？

不能精确拆分。isManagement 是一个合并布尔值；四个子功能是否分别授权，需要明确菜单 ID 或新增粒度更细的导航返回。

Q9：订单到底要不要选门店？

需求图明确留了问号。需分别确认“订单列表是否跨门店聚合”和“订单详情/处理是否必须限定门店”；未确认前不把订单写进固定的需门店或免门店组。

Q10：“我的”页要显示哪些资料？

需求图要求与旧老板助手不同，建议至少展示当前账号、当前项目、可切换项目、角色/权限摘要与当前门店；哪些字段涉及隐私与展示名称，需产品确认。当前两个接口不足以完整生成这一页。

Q11：歇业、闭店、停用门店是否还能选择？

当前接口筛选 storeStatus=0，但还有 openStatus、useStatus 等不同状态。需求图展示了“歇业”，没有说明能否点击；需分别定义“展示”“可进入”“可操作”。

Q12：权限或门店关系在使用中变更怎么办？

切回工作台、切项目、进入功能时重新校验；接口报无角色/无门店时清理失效选择并展示提示。后端每个业务接口仍需独立鉴权，不能只靠首页隐藏 icon。

待确认的产品与技术规则

这些问题会直接影响页面展示和跳转路径。

1. 入口清单与权限来源

11 个 icon 哪些是一级入口？管理下四个子入口是否独立授权？投诉、供应链、0090 分别由哪个菜单 ID / 项目规则控制？

2. 门店选择矩阵

订单是否选门店？数据中心“不选门店”时如何限定统计范围？多门店但仅 1 家 visible=1 时是否直接进入？

3. 异常与状态

0 项目、0 角色、0 入口、0 可选门店、歇业/停用门店分别显示什么文案？歇业门店是否允许查看、是否允许操作？

4. 我的页与切换

我的页展示字段、项目切换入口、门店切换入口放哪里？单入口直达后是否仍保留返回工作台的通路？
