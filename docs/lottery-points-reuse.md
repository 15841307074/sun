# 抽奖积分复用现有流水

会员服务不再读写 `member_lottery_points`，不需要新建它的 10 张分表或新增 Nacos 路由。余额仍在 `wx_member`，防重复与明细统一使用 `points_log.log_code`：`L抽奖业务号:DEBIT / AWARD / REFUND`。

一次事务先锁定会员账户，再查对应业务号流水、改变余额并写流水。同一会员的并发积分操作在账户行上串行；不同会员可以并行。重复成功请求只返回成功，相同业务号金额不同会报错。查询已有流水时包含软删除记录，避免隐藏明细后重复入账。

成功流水沿用 `points_log_status=1`、`deleted=0`；扣款不足或积分上限造成失败时，复用该流水表保存 `points_log_status=0`、`deleted=1` 的内部失败标记，不显示在用户明细。已拒绝的扣款不会因后来充值再次扣款；奖励或退款修复后可以按原业务号重试，将原失败标记更新为正常流水。人工补发不再扣次数或消耗积分。

执行统一脚本 `sql/lottery_release_all.sql` 的 MEMBER 部分：仅给已有 `points_log_0..9` 增加 `(business_id,member_id,log_code)` 查询索引。会员账户和积分流水必须使用现有同一物理库的分片事务。

已使用旧版本的环境：暂停抽奖及发奖任务后执行 MEMBER 部分。脚本将旧账本的 REJECTED 记录补为隐藏失败标记，不改余额；核对每个分片输出的 `missing_success_logs` 都是 0，再切换新会员服务。旧 SUCCESS 原本已与成功积分流水同事务写入；若检查不为 0，应先恢复、核对流水，不能直接切换或删除旧表。旧表不再运行时使用，核对并备份后可由数据库管理员删除。本脚本不自动 DROP，未连接或修改实际数据库。
