有奖问答技术方案

模块：promotion；活动类型：ActivityTypeEnum.ANSWER = 9；渠道类型：ActivityChannelTypeEnum.ANSWER = 12

1. 目标与复用范围

有奖问答作为新的营销活动类型实现，核心是“按活动时间答题 + 按答对数量发奖”。不直接复用抽奖随机奖池，但复用现有营销活动公共能力；活动时间、上下架、门店范围参考 lottery 抽奖活动。

复用 activity 主表复用 activity_store 门店范围复用 activity_channel 渠道复用积分/券/券包/红包/实物发放复用 PV/UV 分析思路

  • 用户在活动有效时间内开始答题，未答完可在同一活动周期内继续。
  • 未完成答题超过活动结束时间后视为结束；活动再次配置或复制新活动后重新开始。
  • 启用中的有奖问答活动不允许直接修改配置，需要先通过启停接口停用，再进入编辑流程。
  • 每答一题提交一次，最后一题提交后按答对数量匹配奖励档位。
  • 答题次数和任务次数按用户手机号维度统计，避免同一手机号绑定不同 memberId 后重复获取次数。
  • 奖品库存不足时向低一档奖励降级，直到没有奖品时返回“很遗憾，奖品已发完”。
  • 库存以数据库原子扣减为最终依据，Redis 只做配置缓存、次数缓存和提交短锁。

5. 核心流程

5.1 开始或继续答题

  1. 校验活动有效、上下架状态、门店范围、当前时间是否在活动时间内。
  2. 从当前登录会员查询手机号，手机号为空时拒绝参与；次数统计、任务统计和未完成记录查找优先使用手机号维度。
  3. 根据活动已有时间/场次规则计算 periodKey。如果活动一天上午一场、下午一场，并且配置按场次重置，则上午和下午生成不同 periodKey。
  4. 查询当前手机号在当前活动、当前 periodKey 下的未完成记录。
  5. 如果存在且活动仍有效，返回原记录和已答明细。
  6. 如果存在但活动已结束，将旧记录置为 status=2。
  7. 扣减或占用一次答题机会，返回题目列表和当前进度。

当前只按天/活动周期的表设计，不足以支持“上午一场、下午一场且次数重置”。要支持该场景，需要增加内部字段 period_key 保存后端根据活动场次算出的周期标识。它不是新增前端入参，也不是新增问答场次配置表，只是记录和缓存的计算维度。

5.2 提交答题与降级发奖

  1. 先用 activity_answer:submit:lock:{recordId} 加短锁，避免瞬时重复提交。
  2. 事务内锁定答题记录；若已完成，直接返回已有结果，不重复扣库存。
  3. 校验提交题目数量必须等于活动题目数。
  4. 逐题对比题目表的 correct_answer，写入轻量答题明细：question_id、selected_answer、answer_result。
  5. 汇总计算 correctCount、wrongCount、accuracy 并更新答题主记录。
  6. 从 correct_count = correctCount 开始向下查找奖励档位。
  7. 每个候选奖励执行数据库原子扣减；扣减成功才写奖励发放记录。
  8. 全部档位不可发时，答题记录仍完成，但返回无奖文案。
UPDATE activity_answer_reward
SET used_num = used_num + 1
WHERE id = #{rewardId}
  AND deleted = 0
  AND (total_num = 0 OR used_num < total_num);

高并发下只认这条 SQL 的影响行数。影响行数为 1 表示抢占成功；为 0 立即降级查上一档，不能依赖 Redis 库存判断发奖。

5.3 答题记录导出

  1. 先按筛选条件分页查询 activity_answer_record，拿到会员、手机号、答题编号、答题数量、正确数量、错误数量、正确率、参与时间、参与门店。
  2. 一次性查询当前活动题目列表，按 id 升序或创建顺序生成导出列：题目名称1、题目名称2、题目名称3。
  3. 按本批次 record_id 批量查询 activity_answer_record_detail，不要一条记录查一次。
  4. 每条记录按 question_id 匹配明细，answer_result=1 导出“正确”，answer_result=0 导出“错误”。
  5. 如果某条题目明细缺失，导出空值或“未答”，并记录日志，避免导出任务中断。

导出不依赖 Redis。ES 可以作为查询加速副本，但不能替代数据库明细，因为提交答题、库存扣减、发奖记录需要事务一致性。

7. 测试重点

  • 同一活动周期未完成可继续；活动结束后未完成记录置为超时结束。
  • 每题提交一次并写入作答明细，重复提交同一题应幂等返回原结果。
  • 最后一题提交后才结算正确数、错误数和奖励；未答完时只返回本题对错、已答数量和下一题。
  • 答对数量命中奖品无库存时，向低档位逐级降级。
  • 奖励剩余 1 个库存时并发 100 次提交，只允许 1 次扣减成功。
  • 同一 recordId 重复提交，只返回已有结果，不重复发奖。
  • 红包超过 24 小时未领取，前台和后台展示已失效。
  • 小程序我的记录、我的奖励、填写地址与后台记录一致。
