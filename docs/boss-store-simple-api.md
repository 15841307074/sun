# 老板助手门店精简列表

## 请求

`GET /app-api/system/store/storeSimpleListByBoss`

部署环境如有网关前缀，沿用原 `storeListByBoss` 的前缀，仅替换最后一段路径。
不需要业务参数；登录凭证、项目及租户上下文与原接口一致。

## 返回

```json
{
  "code": 0,
  "data": [
    {
      "id": "2075055818465878018",
      "storeId": "2075055818465878018",
      "name": "测试门店",
      "storeName": "测试门店",
      "useStatus": 1
    }
  ],
  "msg": ""
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | Long（前端按字符串接收） | 门店ID，与storeId相同 |
| storeId | Long（前端按字符串接收） | 门店ID |
| name | String | 门店名称，与storeName相同 |
| storeName | String | 门店名称 |
| useStatus | Integer，可空 | 供应链门店使用状态：1正常、2停用；沿用数据库原值 |

没有匹配门店时 `data` 返回空数组。请求鉴权与数据库异常沿用项目统一处理，不把查询故障伪装成空列表。

## 范围及性能

- 复用原接口普通门店、直接关联门店、供应链门店的查询条件及权限处理。
- 按storeId去重，普通门店记录优先；不额外筛掉useStatus=2的门店。
- 不保证数据库未显式排序时的返回顺序。
- 门店表仅读取store_id、store_name、use_status；组织关系与层级仅读取ID。
- 跳过原接口visible字段的层级计算、完整对象转换和大量字段序列化。
- 最多5次顺序查询，无逐门店查询、异步数据库并发、事务、加锁读或自动重试。无组织关系时跳过层级查询，无普通门店范围时跳过普通门店查询。
- 总耗时达到500ms输出warn日志，记录组织关系、组织层级、门店关系、普通门店和供应链门店耗时；正常请求使用debug日志。
- 本次不需要数据库结构变更。实际耗时、连接池容量仍受数据量、现有索引、数据库负载影响，不能据此保证任意并发下均无异常。
- 组织层级仍复用FIND_IN_SET筛选语义；如果该阶段慢，应根据慢日志和执行计划进一步优化层级存储，不能仅靠精简返回字段解决。

## 联调检查

使用同一账号和项目，分别调用原、新接口，比较门店ID集合及storeName、useStatus；覆盖仅组织关系、仅门店关系、两者都有、供应链门店、无门店账号。新接口每项仅包含上述5个字段。压测时对比P95耗时与连接池活跃/等待连接数。
